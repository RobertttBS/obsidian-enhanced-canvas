# Harness Diagnosis — obsidian-enhanced-canvas

What most wastes tokens / loses focus / causes errors **in this specific repo**.
First written 2026-07-05; revised 2026-11-15 (sizes re-measured, invariants updated
to five, stale commit refs fixed).

## Top 3 token leaks

### #1 — Reading `main.js` (context blowout)
`main.js` is the compiled bundle (it embeds the built-in OCR's worker with onnxruntime's
JS; even grep output from it can be huge). It is `.gitignore`d and regenerated by `npm run dev`; nothing in it is
useful to read.
- **Fix:** never Read `main.js`. Edit `main.ts` and the `src/*.ts` sources only.
  To confirm a build, run `npx tsc --noEmit`, don't read the bundle.

### #2 — Reading big sources whole when you need one method
`main.ts` (~1,600 lines, every core feature) and `src/ImageTextSearch.ts` (~1,000
lines) are the two large files. Reading either top-to-bottom to change one method
wastes most of the read.
- **Fix:** grep first, then Read with `offset`/`limit`. The method map:
  `grep -nE "register[A-Z]\w*\(|syncAllCanvasProperties|ensureCanvasKeyOrder" main.ts`
  gives the line numbers; read the ±60 lines around the one you need.

### #3 — `AGENTS.md` ≡ `CLAUDE.md` (double-load, double-maintain)
`AGENTS.md` and `CLAUDE.md` are byte-for-byte identical (Codex reads the former,
Claude the latter). Every edit must land in both or they drift.
- **Fix (convention):** any edit to one is mirrored to the other in the same change;
  `diff AGENTS.md CLAUDE.md` after. Codex does not reliably follow cross-file
  pointers, so synced copies beat a one-line pointer.

## Top 3 focus / correctness traps

### #1 — Mixing the two "node" concepts
JSON node (`node.file` = path **string**, in `.canvas` files, typed `JsonNodeRef`) vs
live `CanvasNode` (`node.filePath` = string, `node.file` = **TFile**). Same field
name, different type — the most common bug when editing node code.
- **Fix:** before touching anything named `node`, confirm which kind. See
  `docs/agent/architecture.md` → "Two node concepts".

### #2 — Frontmatter-sync invariants (silent data loss)
Five load-bearing rules: cleanup runs **before** flipping `enableFrontmatter` off;
`canvas` key precedes per-canvas keys (`ensureCanvasKeyOrder` in every write
callback); all edge syncs go through the **debounced queue**; the metadata cache
only gates *whether* a sync runs, decisions read real frontmatter in the callback;
canvas links are matched via `canvasLinkBasename`, never string equality.
- **Fix:** no test catches a regression — read "Frontmatter sync" in
  `docs/agent/architecture.md` before editing any sync path, and verify by hand in
  Obsidian (judgment.md "done" bar). This is a published plugin writing into real
  users' notes; a broken invariant may go unnoticed for days.

### #3 — Hand-rolling the lazy-patcher retry
Every prototype patch goes through `registerLazyPatcher`. The pinned-tab bugs on
Windows (`742646a`, `282fcd3`, `95c2d79`) came from hand-rolled retries that patched
too early, picked an uninitialised leaf, or double-patched; `cb80c3f` consolidated
them into `registerLazyPatcher`.
- **Fix:** call `this.registerLazyPatcher(patch)`; register the uninstaller with
  `this.register(...)`. Never write the retry loop yourself.

## Top 3 error sources (why "done" is easy to fake here)

1. **No tests, no CI, no lint gate.** The only automated check is
   `npx tsc --noEmit`. See `docs/agent/judgment.md` for the real done-bar.
2. **esbuild ignores type errors.** A passing `npm run dev` proves nothing about
   correctness. Run `npx tsc --noEmit` explicitly after edits.
3. **Behavior only observable in Obsidian.** Canvas patches, frontmatter writes, and
   DOM listeners can only be confirmed by reloading the plugin and exercising the
   feature. There is no headless path — do the manual check or say plainly you didn't.

## Two things about this codebase's taste

- **Deliberately minimal.** Past refactors cut ~380 lines of over-engineering
  (`db8cb24`, `27f52be`, `59c08de`). No speculative abstraction, no config for
  constants, reuse over new. The right move is the smallest diff that fits the
  existing shape.
- **Canvas internals are a reverse-engineered guess, not a contract.** `Canvas.d.ts`
  is observed behavior. Prefer official Obsidian API surfaces when a choice exists;
  when a patch "just stopped working", suspect an Obsidian version change first.
