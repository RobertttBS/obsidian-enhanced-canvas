# A. Harness Diagnosis — obsidian-enhanced-canvas

Written 2026-07-05 by an Opus-4.8 session (the last Fable-5-era handoff), auditing
what most wastes tokens / loses focus / causes errors **in this specific repo**.
Environment-wide findings (session-start bloat, contradicting instruction layers,
per-tool hooks) already live in `~/.claude/playbooks/diagnosis.md` — not repeated
here. This file is the repo layer, and the other docs in `docs/agent/` cite it.

## Top 3 token leaks

### #1 — Reading `main.js` (instant context blowout)
`main.js` is the **284 KB compiled bundle**. Opening it once floods context with
~70k tokens of minified output you can never use. It is `.gitignore`d and
regenerated by `npm run dev`.
- **Fix:** never Read `main.js`. Edit `main.ts` and the `src/*.ts` sources only.
  If you need to confirm a build, run `npx tsc --noEmit`, don't read the bundle.

### #2 — Reading `main.ts` whole when you need one method
`main.ts` is **1581 lines / 54 KB** (~15k tokens) — one file holding every feature.
Reading it top-to-bottom to change one patcher wastes most of that.
- **Fix:** grep first, then Read with `offset`/`limit`. The method map is stable:
  `grep -nE "register[A-Z]\w*\(|syncAllCanvasProperties|ensureCanvasKeyOrder" main.ts`
  gives you the line numbers; read the ±60 lines around the one you need.

### #3 — `AGENTS.md` ≡ `CLAUDE.md` (double-load, double-maintain)
`AGENTS.md` and `CLAUDE.md` are currently **byte-for-byte identical** (Codex reads
the former, Claude the latter). Every edit must land in both or they drift; a
session that reads both pays for the same content twice.
- **Fix (convention):** keep them identical — any edit to one is mirrored to the
  other in the same change. Considered making `AGENTS.md` a one-line pointer, but
  Codex does not reliably follow cross-file pointers, so synced copies is the
  safer default. If you ever touch project instructions, update both.

## Top 3 focus / correctness traps

### #1 — Mixing the two "node" concepts
JSON node (`node.file` = path **string**, in `.canvas` files) vs live `CanvasNode`
(`node.filePath` = string, `node.file` = **TFile**). Same field name, different
type. This is the single most common bug when editing node code.
- **Fix:** before touching anything named `node`, confirm which kind. See
  `docs/agent/architecture.md` → "Two node concepts".

### #2 — Frontmatter-sync invariants (silent data loss)
Four load-bearing rules that break user notes if violated: cleanup must run
**before** flipping `enableFrontmatter` off; `canvas` key must precede per-canvas
keys (`ensureCanvasKeyOrder` in every write callback); all edge syncs go through
the **debounced queue** (immediate sync mid-import strips valid links); the
metadata cache only gates *whether* a sync runs, add/remove decisions read real
frontmatter inside the callback.
- **Fix:** these have no test to catch a regression — read the "Frontmatter sync"
  section of `docs/agent/architecture.md` before editing any sync path, and
  verify by hand in Obsidian (judgment.md "done" bar).

### #3 — Hand-rolling the lazy-patcher retry
Every prototype patch must go through `registerLazyPatcher`; hand-rolling the
`active-leaf-change`/`layout-change` retry and forgetting to detach listeners on
success re-patches and breaks Windows pinned tabs (this actually shipped once —
commit `742eb70`).
- **Fix:** call `this.registerLazyPatcher(patch)`; register the uninstaller with
  `this.register(...)`. Never write the retry loop yourself.

## Top 3 error sources (why "done" is easy to fake here)

1. **No tests, no CI, no lint gate.** The only automated check is
   `npx tsc --noEmit`. "It looks right" is not verification — see
   `docs/agent/judgment.md` for the real done-bar.
2. **esbuild ignores type errors.** `main.js` builds green even when the types are
   broken, so a passing `npm run dev` proves nothing about correctness. Run
   `npx tsc --noEmit` explicitly after edits.
3. **Behavior only observable in Obsidian.** Canvas patches, frontmatter writes,
   and DOM listeners can only be confirmed by reloading the plugin in Obsidian and
   exercising the feature. There is no headless path. Budget for a manual check or
   say plainly that you couldn't run one.
